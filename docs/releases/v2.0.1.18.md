# Release v2.0.1.18

Application commit: `1fa868b`.

Deployed on 2026-10-15 from 17:34:41 to 17:34:58 UTC (1:34 p.m. Eastern),
with no games running.

## Incident

From 2026-08-17 to 2026-10-15 no password sign-in or email signup succeeded.
Cloudflare rejected every real Turnstile token with `invalid-input-secret`,
although the secret passed Cloudflare's dummy-token check. Google sign-in was
unaffected. About six people tried and failed in the 12 days before this
release; 32 of the 51 accounts have no Google login.

Password sign-in had a second, older cause, fixed in
[v2.0.1.20](v2.0.1.20.md).

At 17:13 UTC, before this release, the running app was switched to a new
Turnstile widget (site key `0x4AAAAAAFXwLE0rGD_pC4pm`) in memory, and the new
secret was written to `.env`. The previous `.env` is kept on the host as
`backups/env.before-turnstile-20261015`.

## Changes

- New Turnstile site key; `TURNSTILE_SITE_KEY` in `.env` can override it.
- `GET /healthz/auth` checks the Turnstile secret, whether the latest real
  verification failed on the secret, and the Google OAuth client credentials.
- The Turnstile widget records its state (`data-turnstile-state`) so a
  browser check can tell a loaded widget from a wrong key or domain.
- Scheduled "Live sign-in check" workflow (`python/live_check.py`), every 30
  minutes. See [deploy.md](../deploy.md#live-sign-in-check).
- Tokens solved on `localhost` are refused in production.

docker.io/thwar/fortyfives.net@sha256:b940720bc1bf2a5676db92a76f4d952333558f117c8bcf68a24469587fb30c8b

The pre-release online backup `/backups/fortyfives-pre-v2.0.1.18.db` passed
its integrity check, and the restarted backup service published another
verified backup at 17:34:45 UTC. Migrations were already up. Both containers
reported healthy with zero restarts. Database quick-check and foreign-key
checks passed, and all 51 accounts were present.

`/healthz` and `/healthz/auth` returned 200 with all checks `ok`. The live
check passed from a residential connection: the widget reached Cloudflare's
interactive challenge on all three forms, and `/auth/google` led to Google's
sign-in page.
