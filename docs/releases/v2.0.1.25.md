# Release v2.0.1.25

Application commit: `0c163c0`. Deployed on 2026-10-24 from 19:52:37 to
19:52:57 UTC, with no games in progress.

## Changes

- `ueberauth` 0.10.8 → 0.11.0, which signs and verifies the OAuth state
  cookie (`ueberauth.state_param`), so a tampered or unsigned state is
  rejected as `csrf_attack` before the Google callback. `ueberauth_google`
  0.12.1, the latest, still declares `~> 0.10.0`, so `mix.exs` overrides it.
  The signing key is `SECRET_KEY_BASE`, which must stay the same across
  deploys (it already has to, for sessions).
- `ecto_sqlite3` 0.25.0 → 0.26.0 (mostly new migration features; no
  migrations in this release).

Before release, a throwaway ConnTest ran the real request → callback round
trip: with the matching state cookie the callback got past the state check
to Google's token endpoint, and a tampered state or a missing cookie failed
with `csrf_attack`. In production, `/auth/google` redirects to Google and
sets the signed `ueberauth.state_param` cookie (secure, HttpOnly); `/`,
`/play`, `/learn`, `/users/log_in` and `/healthz` answer 200 and
`/healthz/auth` reported `google_oauth` and `turnstile_verifications` `ok`.
A full Google sign-in was not done in production.
