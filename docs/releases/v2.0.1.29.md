# Release v2.0.1.29

Application commit: `6373920`. Deployed on 2026-11-09 from 20:33:24 to
20:33:49 UTC with no games in progress.

## Changes

- **Public or private on every game.** `game_logs.queue` (`public` /
  `private`) and `game_logs.lobby`, the first 8 characters of the private
  lobby id (never the full id, which is the invite). The replay document also
  records `rematch_lobby`, so a private table's "play again" games chain
  together. Rows from before this release have both NULL.
- **Private lobbies are traceable.** Site events from a private lobby carry
  `data.lobby`; a new `refused` event records create/join/bot refusals with
  their reason. Log lines name the lobby on create, reopen, join, leave,
  expiry (with the seated count), game start and end, and when an expired
  link is opened. Health has a `private:` line.
- **Logs survive deploys.** Every container logs to the host's persistent
  journald, tagged with its container name (`journalctl -t
  fortyfives-web-1`). Until now each deploy deleted the logs with the old
  container, which is why the 2026-11-08 private lobby trouble could not be
  read from the logs.

The two 2026-11-08 private games were checked from their event logs: neither
was stuck. Both played normally until the players left; the first after two
tricks (they regrouped in a new seat order), the second during its third hand.
